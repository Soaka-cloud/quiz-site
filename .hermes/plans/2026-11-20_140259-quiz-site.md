# quiz-site — план фундамента (этап Ф) и границы редизайна

**Goal:** рабочий опрос от открытия страницы до строки в Google-таблице, при минимальной вёрстке. Логика зафиксирована тестами, визуал пользователь переделывает сам.

**Architecture:** статический фронт (HTML + один CSS + ES-модули `questions.js` / `survey.js` / `app.js`) отправляет JSON в Google Apps Script Web App (`doPost` + `appendRow`). Данные о вопросах отделены от логики, составление payload вынесено в чистую функцию, чтобы тестироваться без браузера.

**Tech Stack:** HTML5, CSS, ванильный ES-модуль; Playwright Test 1.65 (Chromium) — E2E; Node 22 `node --test` — юнит; Google Apps Script — приёмник.

  .env.example → .env   SURVEY_ENDPOINT (URL Apps Script), .env в .gitignore

### Схема данных

`questions.js` — экспорт массива:

```js
{ id: 'q1', text: 'Вопрос', options: ['Вариант A', 'Вариант B', 'Вариант C'] }
```

Ответы в памяти страницы — `Map<questionId, optionIndex>` (или объект `{q1: 1, q3: 0}`).

### Payload (контракт фронт → Apps Script)

```json
{
  "timestamp": "2026-11-20T14:05:00.000Z",
  "survey": "default",
  "answers": [
    { "id": "q1", "question": "Вопрос", "answer": "Вариант B" }
  ]
}
```

`answer` — **текст выбранного варианта**, а не индекс: таблица должна быть читаемой без знания `questions.js`, а порядок вариантов пользователь будет менять при редизайне. `id` оставляем для мультивыбора/аналитики.

### Схема doPost + appendRow

1. `doPost(e)`: `JSON.parse(e.postData.contents)`; `SpreadsheetApp.openById(props.getProperty('SHEET_ID'))`; лист по имени из `SHEET_NAME` (по умолчанию «Ответы»), если листа нет — создать.
2. Шапка (при пустом листе): `Timestamp | Survey | <Вопрос 1> | <Вопрос 2> | ...` — колонки по `answers[].question` из первого же запроса.
3. `appendRow([timestamp, survey, ...ответы в порядке вопросов])`. Порядок фиксирован порядком `answers` (фронт отправляет их в порядке `questions.js`), поэтому колонки не «поедут».
4. Ответ: `ContentService.createTextOutput(JSON.stringify({ok:true}))` с `setMimeType(JSON)`; при ошибке — `{ok:false, error: ...}` и `console.error` (видно в Executions).
5. `SHEET_ID` — **только** в Script Properties (`PropertiesService.getScriptProperties()`), в коде `props.getProperty('SHEET_ID')`.

### Ключевое решение по CORS

Apps Script Web App **не может** отдать кастомные заголовки, включая `Access-Control-Allow-Origin` — `ContentService` позволяет управлять только MIME-типом. На `POST` с `Content-Type: application/json` браузер отправляет **preflight OPTIONS**, который Apps Script обработать не умеет (`doOptions` не вызывается), → запрос падает «Failed to fetch».

Поэтому единственная рабочая схема — **«простой» запрос без preflight**:

- `fetch(url, { method: 'POST', body: JSON.stringify(payload), headers: { 'Content-Type': 'text/plain;charset=utf-8' }, redirect: 'follow' })`;
- парсим тело на стороне `doPost` через `JSON.parse(e.postData.contents)` — содержимое идентично, отличается только заявленный MIME;
- `mode: 'cors'` не ставим — при `text/plain` он не нужен; ответ читаем через `response.text()` и `JSON.parse` (при `redirect: 'follow'` ответ приходит непрозрачным для `response.json()` в части браузеров).

Альтернативы и почему отклонены: *реальный preflight* — невозможен (нет `doOptions`); *прокси* (свой воркер) — противоречит «внешних зависимостей нет»; *`<form>` с `application/x-www-form-urlencoded`* — не поддерживает JSON без танцев с именами полей, и нет контроля над ответом (страница уйдёт на `script.google.com`).

**Ограничение, которое надо знать:** этот же URL, включённый в `Content-Security-Policy connect-src`, должен быть в политике; у нас CSP нет — не блокирует.

### ТЗ на тесты

**Слой 1 — юнит (`node --test`, чистая логика в `survey.js`):**

| # | Тест | Доказывает |
|---|---|---|
| U1 | `buildPayload([{id,optionIndex}], questions, now)` → `answers[].answer` = текст варианта, порядок как в `questions` | контракт payload |
| U2 | `timestamp` — ISO-строка, приходит из инъекции `now` (детерминизм) | не текущее время в тесте |
| U3 | `selectAnswer` заменяет предыдущий выбор того же вопроса, не дублирует | одна опция на вопрос |
| U4 | `renderQuestion` кладёт в разметку крючки `survey-question`, `answer-option`, `data-question-id` | контракт редизайна (проверяется и E2E) |
| U5 | `submitUrl()` берёт URL из конфига (`window.SURVEY_CONFIG`), а не из литерала | секрет вне кода |

**Слой 2 — E2E (`npx playwright test`, Chromium, статический сервер `webServer`):**

| # | Сценарий | Доказывает |
|---|---|---|
| E1 (Ф3) | открывается, рендерятся все вопросы и варианты, виден `progress-bar` | страница живая |
| E2 (Ф3) | клик по варианту → выбран (класс/атрибут `aria-checked`/`data-selected`), прогресс растёт | выбор работает |
| E3 (Ф3) | выбор ответа на все вопросы + клик `submit-button` → виден `thank-you-screen`, список вопросов скрыт | конец сценария без сервера |
| E4 (Ф4) | `page.route('**/macros/s/**')` перехватывает POST: тело — валидный JSON с `timestamp` и `answers` по вопросам | корректный payload |
| E5 (Ф4) | ответ заглушки `{ok:true}` → экран благодарности; ответ `500` → экран ошибки/сообщение, благодарность НЕ показана | обработка отказа |
| E6 (Ф4) | `submit-button` заблокирован до ответа на все вопросы | нельзя отправить пустое |

**Перехват сети:** `page.route()` (Playwright route-API), не stub `window.fetch`. Причина: mock подменяет функцию внутри страницы и не ловит ошибки реального `fetch` (CORS, заголовки, редирект), а `page.route` видит фактический запрос — метод, URL, тело, заголовки — и возвращает контролируемый ответ. Реальный POST в живую таблицу из тестов **не идёт** (ограничение задачи).

### Поверхности для редизайна

**Пользователь меняет (и только это):**

| Что | Где | Комментарий |
|---|---|---|
| Цвета, шрифты, отступы, тени, анимации | `style.css` | единственный файл стилей; можно переписать целиком |
| Разметку внутри вопроса/варианта/экрана | `index.html` | можно менять вложенность, добавлять обёртки, менять тексты заголовков |
| Тексты вопросов и вариантов | `questions.js` | файл данных, структура `{id, text, options[]}` — контракт |

**Гарантии, что логика при этом не трогается:**

- селекторы JS привязаны **только** к пяти крючкам + `data-question-id` / `data-option-index`; ни один селектор не смотрит на теги, вложенность или CSS-классы оформления;
- `app.js` не создаёт стилей: ни `style=`, ни `element.style`, ни `<style>` — страж-тест E7 падает, если это появилось;
- контракт редизайна закреплён тестами: если пользователь удалит крючок, E2/E3 упадут с понятным сообщением, а не «тихо сломается»;
- ноль зависимостей от внешних библиотек — нет `tailwind`, нет сборки, нет `npm run build`.

**Что пользователю НЕ надо менять:** `app.js`, `survey.js`, `apps-script/Code.gs` (кроме `SHEET_NAME` при желании переименовать лист).

## Риски и оговорки

- **`file://` не работает**: ES-модули грузятся только по HTTP. Локальный запуск — `python -m http.server 8000`, тесты поднимают сервер сами.
- **Не совсем «pytest»**: стек проекта — Node/Playwright; `pytest --cov` здесь не применим без второго стека. Прогон отчёта — `npx playwright test --reporter=html` + юнит `node --test`; если нужна именно таблица покрытия — добираю `c8` (`npx c8 node --test`) и отдаю текстовую таблицу.
- **Ответ Apps Script всегда 200**, даже при внутренней ошибке, если код не поймал исключение — поэтому `doPost` возвращает `{ok:false}` в теле, а фронт проверяет тело, не только статус.
- **Лимиты Apps Script** (~30 с на выполнение, квота на запросы) для анкеты несущественны.
